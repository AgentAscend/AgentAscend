## Likely causes
- Local failure is expected when dev server is not running.
- Intermittent `500` on `/marketplace/live` likely indicates transient runtime issue (cold start race, data serialization edge, or sporadic upstream/db timing), not persistent outage.

## Suggested fixes
1. Add targeted logging/alert correlation for `/marketplace/live` 5xx events (timestamp + request ID + traceback context).
2. Run repeated probe + log capture window to reproduce intermittency deterministically.
3. Keep serializer regression tests (`test_marketplace_live_serialization.py`) in pre-merge gate.
4. If local verification is needed, run local backend and repeat `/health` + `/openapi.json` checks.

## MVP blocking status
- **Not hard-blocking right now** for baseline health/payment-route visibility.
- **Potential soft blocker** if `/marketplace/live` intermittent 500 recurs during user-facing demos.
