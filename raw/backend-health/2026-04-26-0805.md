## 2) Endpoints that failed
- `POST /payments/create` with minimal probe payload → **422**
- `POST /payments/verify` with minimal probe payload → **422**
- `GET /users/healthcheck-user/access` without auth → **401**
- `GET /users/healthcheck-user/payments` without auth → **401**
- `POST /tools/random-number` with JSON body only (no query param) → **422**
- `GET /marketplace/listings` without required query params → **422**
- `POST /marketplace/listings` with empty body → **422**

## 3) Exact non-secret error messages
- `/payments/create` 422: `Extra inputs are not permitted` (for `feature_name` in probe body)
- `/payments/verify` 422: `Field required` (`user_id`) and `Extra inputs are not permitted` (`payment_id` in probe body)
- `/users/.../access` 401: `{"error":{"code":"unauthorized","message":"Missing Authorization header"}}`
- `/users/.../payments` 401: `{"error":{"code":"unauthorized","message":"Missing Authorization header"}}`
- `/tools/random-number` 422 (body-only call): `Field required` at `query.user_id`
- `/marketplace/listings` 422 (GET): `Field required` for `creator_user_id`
- `/marketplace/listings` 422 (POST): multiple `Field required` validation errors for required body fields

## 4) Likely cause
- No outage detected on core backend health.
- Most “failures” are expected request-validation/auth failures from unauthenticated or intentionally minimal probe payloads.
- User access/payments endpoints are protected by auth middleware.
- Payments and marketplace create endpoints enforce strict schemas.
- Gated tool endpoint expects `user_id` as query parameter (not JSON body).

## 5) Suggested fix
- No urgent backend fix required from this check.
- Improve API consumer clarity (docs/frontend integration):
  - Ensure clients send the exact expected payment payload schemas.
  - Pass `user_id` as query parameter for `/tools/random-number` (or standardize endpoint to body input, then update OpenAPI + frontend).
  - Ensure auth header is attached before calling `/users/{user_id}/access` and `/users/{user_id}/payments`.

## 6) MVP blocker status
