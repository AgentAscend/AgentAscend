## 3) Exact non-secret error messages
- `{"error":{"code":"unauthorized","message":"Missing Authorization header"}}`

## 4) Likely cause
- User-scoped access/payments endpoints are now auth-protected and reject unauthenticated requests.
- This is likely expected behavior, but it may differ from older unauthenticated local examples in project memory.

## 5) Suggested fix
- For health cronjobs, keep unauthenticated checks to public-safe endpoints (`/health`, `/openapi.json`, marketplace live, payment-gated tool handshake).
- Add a read-only cron auth token/JWT path for authenticated smoke checks of user endpoints.
- If frontend still calls these without auth, update frontend to always attach `Authorization: Bearer <token>`.

## 6) MVP block assessment
- **Not a hard MVP blocker** if frontend/auth flow is already implemented.
- **Potential integration blocker** if any client still expects unauthenticated access to `/users/{user_id}/access` or `/users/{user_id}/payments`.
