# Backend Health Check — 2026-04-27 04:01 (local)

## Scope
- Target API: `https://api.agentascend.ai`
- Checked:
  - `GET /health`
  - Live OpenAPI route presence for: payments create, payments verify, user access, user payments, gated tool, marketplace
  - Safe live probes for read-only endpoints and method checks
- Local `/health` check: **skipped** because no local server was listening on port `8000`.

## Results

### 1) Endpoints that passed
- `GET https://api.agentascend.ai/health` → **200**
  - Body: `{"status":"ok"}`
- `GET https://api.agentascend.ai/marketplace/browse` → **200**
  - Body starts with: `{"status":"ok","listings":[...` (non-empty)
- OpenAPI presence (`/openapi.json` returned 200) confirms routes exist:
  - `POST /payments/create`
  - `POST /payments/verify`
  - `GET /users/{user_id}/access`
  - `GET /users/{user_id}/payments`
  - `POST /tools/random-number`
  - `GET /marketplace/live`
  - `GET /marketplace/browse`
- Method checks confirming route mount (safe, no side effects):
  - `GET /payments/create` → 405 `{"detail":"Method Not Allowed"}`
  - `GET /payments/verify` → 405 `{"detail":"Method Not Allowed"}`
  - `GET /tools/random-number` → 405 `{"detail":"Method Not Allowed"}`

### 2) Endpoints that failed
- `GET https://api.agentascend.ai/marketplace/live` → **500**

### 3) Exact non-secret error messages
- `GET /marketplace/live` response body: `Internal Server Error`
- Response header included request id: `x-railway-request-id: Wo4n8XlHSyOXay20n6XIxQ`
- Auth-protected endpoints (not a system fault, but unauthenticated test result):
  - `GET /users/real3/access` → 401 `{"error":{"code":"unauthorized","message":"Missing Authorization header"}}`
  - `GET /users/real3/payments` → 401 `{"error":{"code":"unauthorized","message":"Missing Authorization header"}}`

### 4) Likely cause
- The `marketplace/live` handler is mounted but throwing an unhandled backend exception in production.
- Most likely data-shape/serialization issue in live listing conversion (e.g., malformed `tags_json` or strict model coercion failure) because:
  - `/marketplace/live` fails with 500
  - `/marketplace/browse` succeeds against same published listings table
  - Local route code for `/marketplace/live` performs stricter row-to-model conversion.

### 5) Suggested fix
1. Inspect Railway backend logs for request id `Wo4n8XlHSyOXay20n6XIxQ` to get traceback.
2. Patch `/marketplace/live` row parsing defensively:
   - Guard `json.loads(tags_json)` with fallback to `[]`
   - Skip or sanitize malformed listings instead of hard-failing the whole response
   - Add structured error logging with listing id.
3. Add regression test for malformed `tags_json`/nullable fields in published listings.

### 6) MVP impact
- **Does not block core payment-gated MVP loop** (health + payment/auth routes are present).
- **Does block marketplace live feed reliability**, which can block marketplace-facing UX and trust.
