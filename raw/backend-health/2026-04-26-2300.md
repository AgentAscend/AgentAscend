## 4) Likely cause
- Backend is healthy and deployed, but route contract appears to have evolved:
  - Gated tool path appears to be `/tools/random-number` (present in OpenAPI), not `/tools/gated/random-number`.
  - User routes now enforce Authorization, so unauthenticated cron probing cannot validate business responses.
- No evidence of payment-route outage; validation errors are expected for empty payloads.

## 5) Suggested fix
- Align route contract across docs/frontend/cron checks:
  - Replace legacy expectation `/tools/gated/random-number` with current OpenAPI path(s), or add backward-compatible alias route.
- For cron monitoring, add an auth-aware health probe mode using a scoped non-sensitive service token (if approved) to validate authenticated user endpoints end-to-end.
- Keep unauth probes for public liveness and schema presence as baseline checks.

## 6) MVP impact
- **Not a backend-down blocker**: health + core payment endpoints are live.
- **Potential integration blocker** if frontend or automation still calls legacy gated-tool path (`/tools/gated/random-number`).
- Auth-protected user endpoints are **not validated end-to-end** in this run due to missing credentials (expected by policy).
