# Hermes Runtime Rules Audit — 2026-04-27

## Scope Reviewed
- `system/hermes_runtime_rules.md`
- `agent_runtime/policies/shell_allowlist.json`
- `agent_runtime/policies/write_allowlist.json`
- `agent_runtime/policies/protected_paths.json`
- `system/cronjobs/approved-cronjobs.md`
- `backend/app/routes/jobs.py`
- `backend/app/config/agent_runtime.yaml`
- `backend/app/services/runtime_config.py`

## Current Capability Level (Observed)
**Level: L1.5 (report-first with guarded runtime execution)**
- Strong documentation-level constraints exist (knowledge boundaries, payment authority, split-brain tiering).
- `/jobs` admin gate is fail-closed in production when `AGENT_RUNTIME_ADMIN_TOKEN` is missing.
- Local safe-mode fallback exists for private/loopback clients.
- Scheduler defaults are conservative for premium (`premium_model_requires_manual_approval: true`) but permissive for job suggestion (`allow_auto_spawn_jobs: true`).

## What Is Good
1. **Explicit boundary rules** in runtime rules (raw/wiki/system separation).
2. **Protected path model** present (`system/**`, `.env*`, keys, db artifacts).
3. **Shell allowlist and deny patterns** present.
4. **Cron approval ledger** exists in `system/cronjobs/approved-cronjobs.md`.
5. **Production fail-closed** for `/jobs` without runtime token.

## Missing / Weak Runtime Rules
1. **Allowlist is declarative, not enforced by backend runtime code path** (policy files exist but no central enforcement middleware around shell/file operations in backend).
2. **No signed policy versioning** (rules can drift without a hash/signature checkpoint).
3. **No explicit network egress policy** (domains/protocols allowed for autonomous jobs are not restricted).
4. **No per-job capability matrix** (jobs are not bound to an allowlisted command/profile scope at execution).
5. **No hard anti-secret-ingestion rule for historical artifacts** (conversation logs can include env/CLI traces).
6. **Safe mode fallback is IP-based** and should not be treated as a durable auth boundary.

## Recommended Skills / Tool Restrictions
1. Create skill: **`runtime-policy-verify`**
   - Validate policy files + check enforcement hooks before each deploy.
2. Create skill: **`cronjob-risk-gate`**
   - Require risk tier, data sensitivity tier, and explicit command budget per job.
3. Restrict tool use for autonomous jobs:
   - Disallow write outside `raw/**` for scheduled report jobs.
   - Disallow git mutation (`git add/commit`) in cron context by default.
   - Disallow shell commands with inline secrets/env assignment patterns.
4. Add explicit **external posting deny** capability flag for all cron runners.
5. Add **max output size + redaction filter** before report persistence.

## Next Runtime Improvements (Priority)
1. **P0**: Enforce policy files in code (single guard module for shell + write + protected paths).
2. **P0**: Add redaction scanner on scheduler outputs before save.
3. **P1**: Add capability profiles per `job_type` (allowed commands, max runtime, max files touched).
4. **P1**: Add immutable weekly runtime snapshot (`raw/hermes-runtime-audits/`) with policy checksums.
5. **P2**: Add runtime anomaly alerts (unexpected command pattern, repeated auth failures, secret pattern match).

## Risk Notes
- Runtime governance is **good at policy intent** but **incomplete at policy enforcement guarantees**.
- Jobs/auth guard quality is better than average, but autonomy safety still depends on discipline and conventions more than hard technical controls.

## Overall Assessment
**Moderate maturity** with clear trajectory. Strongly recommend moving from documented constraints to enforced constraints in the next hardening cycle.
