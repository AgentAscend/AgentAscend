## Phase 3 — Issues by Severity

### CRITICAL
1. **`GET /marketplace/live` returns 500 in production**
   - Root cause from Railway logs:
     - `pydantic ValidationError` in `backend/app/routes/marketplace.py::_listing_from_row`
     - `ListingRecord` expects strings for `created_at`, `updated_at`, `published_at`
     - Postgres driver returns `datetime` objects
   - Impact: live marketplace endpoint unavailable.

### HIGH
2. **`default-git-status-summary` repeated failures in scheduler history**
   - Cause: git dubious ownership guard under scheduler service context.
   - Impact: recurring monitor noise + false failed run alerts.

### MEDIUM
3. **Execution ledger scheduler linkage currently inactive**
   - `scheduled_job_run` execution count is 0.
   - Not a breakage (feature-flag controlled), but reduces scheduler observability.

### LOW
4. No `cronjobs/scheduled_tasks/jobs` tables (informational only; architecture uses `scheduled_jobs`).

## Phase 5 — `/marketplace/live` 500 Targeted Investigation

### Evidence
- `curl https://api.agentascend.ai/marketplace/live` => HTTP 500.
- Railway logs show traceback and `ValidationError` for timestamp fields typed as `datetime`.

### Local safe fix implemented

- Added `_as_iso_string()` to normalize `datetime -> ISO string`.
- Added `_safe_tags()` defensive JSON parsing for `tags_json`.
- Hardened `price_amount` cast with null-safe default.

- `tests/test_marketplace_live_serialization.py`
