# Obsidian Graph Maintenance Runbook

Related: [[AgentAscend]], [[Ops Runbook]], [[Hermes]]

## 1. Why floating graph dots happen
Floating dots usually come from date-based raw notes generated by audits, cron reports, backend health checks, git status reports, research notes, or community drafts. These files often have no outgoing `[[wikilinks]]`, no frontmatter `related:` list, and no visible `Related:` line.

## 2. Raw evidence vs wiki hubs
Raw evidence preserves original observations and should stay short-linked, not rewritten. Wiki hubs summarize durable concepts and connect clusters: [[AgentAscend]], [[Launch Readiness]], [[Payment Access Control]], [[Pump.fun Tokenized Agent Payments]], [[Marketplace]], [[Execution Ledger]], [[Scheduler]], [[Cronjobs]], [[Hermes]], [[Agent Architecture]], [[Ops Runbook]], [[Known Issues]], [[Roadmap]], and [[Community]].

## 3. Manual maintenance steps
1. Scan markdown in `raw/`, `wiki/`, `docs/`, `skills/`, `learning/`, `MEMORY.md`, and `AGENTS.md`.
2. Identify files with zero outgoing wikilinks, no frontmatter, and no visible `Related:` line.
3. Choose no more than 50 high-value raw notes per batch.
4. Add safe evidence frontmatter and a visible `Related:` line.
5. Update concise `Recent Evidence` links on relevant wiki hubs.
6. Write/update `raw/wiki-maintenance/latest-graph-orphan-report.md`.
7. Run secret scan and `git diff --check`.

## 4. Folders to scan
Primary: `raw/`, `wiki/`, `docs/`, `skills/`, `learning/`, `MEMORY.md`, `AGENTS.md`.
High-volume raw folders: `raw/backend-health`, `raw/git-status`, `raw/account-recovery`, `raw/community-drafts`, `raw/wiki-maintenance`, `raw/db-integrity`, `raw/payment-audits`, `raw/daily-status`, `raw/code-quality`, `raw/research`, `raw/trend-scans`, `raw/cronjob-audits`, and `raw/post-deploy-audits`.

## 5. Files not to touch
Do not edit backend/frontend/test/node-helper code for graph maintenance. Do not stage `.obsidian/graph.json` or `.obsidian/workspace.json`. Do not delete raw evidence. Do not rewrite public tx signatures.

## 6. Safety scan rules
Before commit, scan touched markdown for DB URLs, RPC URLs, QuickNode URLs, auth tokens, cookies, private keys, seed phrases, `txBase64`, signed transactions, raw request bodies, raw response bodies, raw DB rows, raw `metadata_json`, and raw `payload_json`. Known public tx signatures and public wallet/token addresses are allowed.

## 7. Commit rules
Stage only intended docs/wiki/raw/skills/learning markdown files. Never stage `.obsidian` workspace files or backend/frontend/test/node-helper files. Keep commits docs-only and isolated.

## 8. Cadence
- After every major Hermes work session.
- Daily if many raw notes are created.
- Weekly full graph cleanup.
